# nvim-pack Migration Design

**Date:** 2026-08-26
**Status:** draft — awaiting user approval
**Classification:** architectural (new config subsystem; no existing `vim.pack` flow to change)

---

## 1. Goal

Migrate Jonathan's Neovim config from the LazyVim distribution (backed by
`lazy.nvim`) to a self-owned config at `~/.config/nvim-pack` backed by
Neovim's native `vim.pack` plugin manager. The new config must be
functionally equivalent to the current one for the features Jonathan
actually uses, with the LazyVim extras deferred to a follow-up phase.

## 2. Scope

### In scope (Phase 1)

- Port Jonathan's custom config: `lua/config/{options,keymaps,autocmds}.lua`.
- Port Jonathan's custom plugins: `conform`, `kotlin`, `lens`, `lightbulb`,
  `symbol-usage`, `tiny-autosave`, `workspace-diagnostics`.
- Replace `lazy.nvim` with `vim.pack` as the plugin manager.
- Preserve all non-LazyVim runtime behavior: colorscheme, LSP, completion,
  treesitter, formatting, keymaps, options, autocmds.
- Cutover via symlink so the old config stays intact and revertible.

### Out of scope (Phase 2, deferred)

- LazyVim extras listed in `lazyvim.json` (40+ plugins). These are deferred
  pending Jonathan's confirmation of which he actually uses day-to-day.
- Any new features or config changes beyond what exists today.

## 3. Why `vim.pack` and not `lazy.nvim`

- Neovim 0.12+ ships a built-in plugin manager (`vim.pack`); the running
  build is 0.13-dev, which has it.
- `vim.pack` removes a dependency (no `lazy.nvim` clone, no `lazy-lock.json`
  churn) and bootstraps from a committed lockfile on new machines.
- LazyVim's spec format (`import`, `config = function()`, `opts`, `event`,
  `cmd`, `keys`) is `lazy.nvim`-specific. `vim.pack` only understands
  `src`/`name`/`version`/`data` plus load callbacks. Therefore every plugin
  that needs configuration gets an explicit `setup()` call in the new
  config — this is the main translation cost, and it is why the LazyVim
  extras are deferred rather than bulk-ported.

## 4. Target layout

```
~/.config/nvim-pack/
├── init.lua                    vim.pack.add({...}) bootstrap; require("config.*")
├── lua/
│   ├── config/
│   │   ├── init.lua            options + keymaps + autocmds (ported verbatim)
│   │   ├── plugins.lua         per-plugin setup() calls
│   │   └── lsp.lua             nvim-lspconfig setup + server configs
│   └── plugins/                ported plugin specs
│       ├── conform.lua
│       ├── kotlin.lua
│       ├── lens.lua
│       ├── lightbulb.lua
│       ├── symbol-usage.lua
│       ├── tiny-autosave.lua
│       └── workspace-diagnostics.lua
├── nvim-pack-lock.json         generated by vim.pack; committed
├── stylua.toml                 spaces, width 120 (match current)
├── .editorconfig               tabs for lua (match current)
├── .neoconf.json               neodev for lua_ls (match current)
└── (no lazy-lock.json, no lazy.nvim)
```

## 5. Cutover mechanism (symlink)

```
~/.config/nvim-source/     ← existing lazyvim config, untouched (rename from ~/.config/nvim)
~/.config/nvim-pack/       ← new vim.pack config
~/.config/nvim → symlink to ~/.config/nvim-pack
```

Steps:

1. `mv ~/.config/nvim ~/.config/nvim-source`
2. Build `~/.config/nvim-pack` (new config).
3. `ln -s ~/.config/nvim-pack ~/.config/nvim`

Neovim reads `~/.config/nvim` and gets the new config. Revert by swapping the
symlink target back to `nvim-source`. Zero downtime; one command to roll back.

## 6. Translation rules

| Current (`~/.config/nvim`) | New (`nvim-pack`) | Note |
| --- | --- | --- |
| `init.lua` → `require("config.lazy")` | `init.lua` → `vim.pack.add({...})` then `require("config.init")` | lazy.nvim replaced |
| `lua/config/lazy.lua` | deleted | functionality moves into `init.lua` |
| `lua/config/options.lua` | `lua/config/init.lua` (options section) | port verbatim |
| `lua/config/keymaps.lua` | `lua/config/init.lua` (keymaps section) | port verbatim |
| `lua/config/autocmds.lua` | `lua/config/init.lua` (autocmds section) | port verbatim |
| `lua/plugins/*.lua` (lazy.nvim spec tables) | `lua/plugins/*.lua` + `lua/config/plugins.lua` setup calls | rewrite spec → setup |
| `lazy-lock.json` | deleted | obsolete |
| `nvim-pack-lock.json` (already present) | regenerated by `vim.pack` | committed |

### Plugin spec → setup translation

A lazy.nvim spec like:

```lua
return {
  { "folke/which-key.nvim", config = function() require("which-key").setup({}) end },
}
```

becomes:

```lua
-- lua/plugins/which-key.lua
vim.pack.add({ "https://github.com/folke/which-key.nvim" })

-- lua/config/plugins.lua
require("which-key").setup({})
```

Plugins that need no configuration are listed as bare URLs in `init.lua`.
Plugins that need configuration get a `setup()` call in
`lua/config/plugins.lua`, executed after `vim.pack.add`.

## 7. Behavior to preserve (from current config)

- **Options:** leader `,`, localleader `,`, backup, cmdheight 0, mousescroll,
  title, spell, backspace, breakindent, smoothscroll, conceallevel 2,
  provider disabling, `root_spec`, `autoformat`, `lazyvim_cmp`/`picker`
  globals, filetypes `astro`/`Podfile`, silent-by-default keymaps.
- **Keymaps:** all custom mappings in `keymaps.lua` (Brave search, `+`/`-`,
  `dw`, window nav, scroll-centering, `U` redo, `<leader>ciL` linter).
- **Autocmds:** conceallevel 0 on json/jsonc/markdown, formatoptions
  cleanup, cursorline toggle, numbertoggle.
- **Plugins:** conform, kotlin, lens, lightbulb, symbol-usage, tiny-autosave,
  workspace-diagnostics.
- **Completion:** blink.cmp (already in lockfile).
- **Colorscheme:** tokyonight.
- **Treesitter:** rust, golang, typescript (+ javascript, json, yaml, toml,
  markdown, etc.); built via `:TSBuild` per filetype rather than lazyvim's
  `ensure_installed` auto-install.
- **LSP:** nvim-lspconfig plus Jonathan's server settings (rust-analyzer,
  gopls, ts-language-server / tsserver, plus kotlin and any others currently
  configured).

## 8. Verification

1. `nvim --headless` starts without errors and `:messages` is clean.
2. `vim.pack` lockfile is regenerated and consistent.
3. `:LazyVim`-dependent commands are gone; `:packadd`-loaded plugins resolve.
4. Each ported plugin's setup runs: `:ConformInfo`, `:Kotlin*`, `:Lens`,
   `:Lightbulb`, `:SymbolUsage`, `:TinyAutoSave`, workspace diagnostics all
   behave as before.
5. Keymaps and options match the current config (diff `:map`, `:set` output
   against `nvim-source`).
6. Cutover revert test: swap symlink back to `nvim-source`, confirm the old
   config still works.

## 9. Risks and open items

- **RISK:** Some LazyVim defaults that Jonathan relies on (e.g. `mini-snippets`
  for snippets, `harpoon2`, `leap`, `inc-rename`) may silently stop working
  if not explicitly ported in Phase 2. Mitigation: Phase 1 verification checks
  for missing commands/mappings; Phase 2 ports whatever is flagged.
- **RISK:** `vim.pack` is still experimental in 0.13-dev. Mitigation: pin
  versions in the lockfile; keep `nvim-source` intact for rollback.
- **OPEN:** Which LazyVim extras Jonathan actually uses (deferred to Phase 2).
- **OPEN:** Exact treesitter language set and LSP server list for
  rust/golang/typescript (assumed to match the current config).
